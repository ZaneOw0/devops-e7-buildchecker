**第一个真实缺陷（E13 Issue #1 草稿，由 241880106 本人负责）**

- 现象：`four-services` 中四个容器均 healthy，`draft`、`full-check` 成功；EChecker 返回 HTTP 422：`fatal: detected dubious ownership in repository at '/course/work/ci-e14/base-project'`，外层 `FAILED`。
- 原因：GitHub runner 上仓库与 `orchestrate.py` 克隆出的 `base-project/target-project` 属于 `runner` 用户，而 `compose.yaml` 让容器以 `user: "0:0"` 运行；容器内 root 执行 `git rev-parse` 时，git 的 safe.directory 检查拒绝。服务器上全程是 root，所以正常运行时复现不出来。课程模板此前没有在 Git 平台上跑过。
- 服务器复现：把 A05 项目的一个克隆 `chown` 给 uid 1001，在 `course-e11e12:241880106` 容器（git 2.47.3）里以 root 执行 `git rev-parse HEAD`，得到同样的 `dubious ownership`，退出 128；加上 `GIT_CONFIG_COUNT=1`、`GIT_CONFIG_KEY_0=safe.directory`、`GIT_CONFIG_VALUE_0=*` 后返回 `90646db…`，退出 0。
- 严重度：阻断（必需 CI 不绿，不能进入 RC）。
- 修复方向（二选一，PR 里说明理由；重新 Re-run 同一提交不会变绿）：
  - (a) 在 `labs/e13e14/compose.yaml` 每个服务的 `environment` 中加入 `GIT_CONFIG_COUNT: "1"`、`GIT_CONFIG_KEY_0: safe.directory`、`GIT_CONFIG_VALUE_0: "*"`。注意各服务的 `environment` 会整体覆盖 `x-common` 里的同名键。
  - (b) 只改工作流，让编排与证据目录的属主和容器用户一致。
- 验收：同一工作流在修复提交上 `four-services` 为绿色，五阶段成功；服务器上四容器跑固定样例回归仍然通过。

**修复进展（241880106，个人分支 `student/241880106/e13-e14`）**

- 采用方案 (a)：在 `x-common` 的 `environment` 中加入上述三项 `GIT_CONFIG_*`，并给它定义锚点 `&common-env`；四个服务都改为 `<<: *common-env` 后再写 `E14_ROLE`。这样也修正了原来的问题：各服务的 `environment` 整体覆盖公共项，导致 `PYTHONPATH` 丢失。`docker compose config` 展开后，四个服务都带有 `E14_ROLE`、`GIT_CONFIG_VALUE_0`、`PYTHONPATH`、`PYTHONDONTWRITEBYTECODE`。

## 4. 组员同步步骤（241880353、241880617 各自执行）

在自己的服务器目录执行，不要动别人的目录：

```bash
cd ~/devops-students/<学号>/buildchecker
git status --short                       # 必须为空；有改动先辨认来源并保存
git fetch origin
git switch -c student/<学号>/e13-e14 origin/e13-e14-integration
git config --local user.name <学号>        # run_e11e12.py 要求本地 user.name 为学号

# 1) 基线
python3 run_e11e12.py test > work/e13-baseline-<学号>.log 2>&1; echo TEST_EXIT=$?
python3 run_e11e12.py run --request data/e12-tuna.json --out work/e13-baseline-<学号>-01   # 若本目录无 e12-tuna.json，从 241880106 的 data/ 复制 candidate-tuna.Dockerfile 与 e12-tuna.json

# 2) 恢复 A05 项目（以交接包为准）
PKG=reports/E13/A-project
(cd $PKG && sha256sum -c SHA256SUMS)
git clone $PKG/a05-project.bundle data/a05-project
cp $PKG/candidate.Dockerfile data/a05-candidate.Dockerfile
cp $PKG/request-e12.json data/a05-e12.json
cp $PKG/request-e11-a.json data/a05-e11-a.json

# 3) 推送个人分支（本人账号）
git -c http.version=HTTP/1.1 push -u origin student/<学号>/e13-e14
```

注意事项：

- **Docker 构建串行**：3.5 GiB 内存，大家同时做 DRAFT 构建会互相抢资源。开跑前在群里报一声。
- **Compose 端口固定**：`labs/e13e14/compose.yaml` 写死了 `127.0.0.1:18081–18084`，同一时间只能有一个人的四容器在跑。用 `-p e14-<学号>`，跑完只 `down` 自己的项目。
- **每个用例新开 `work/` 目录**，不覆盖旧证据，失败的证据也保留。
- 不要停共享的 Docker 服务，不要清理别人的容器或镜像。
