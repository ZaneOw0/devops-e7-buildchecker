# ADR：E12 跨机联调的接入方式与组级验收口径

编号、日期、作者：ADR-E11E12-241880106 / 2026-11-17 / 李泽同 241880106

## 背景

A05 组在 `e11-e12-integration` 上已有两份个人交付：241880353 完成真实项目 E11-A 并把增量报告交给 B 组（PR #10），241880617 在 A 组仓库内跑通真实项目五阶段并修复 pinned FROM 校验（PR #12）。两份报告的 API 联调都只在 API 所在服务器的 `127.0.0.1` 上完成，手册 02 §3 要求的“另一方在自己的终端建立 SSH 转发”没有实际证据。本人负责组级联调验收与交接，需要决定：

1. 跨机访问用什么客户端、走什么路径；
2. 组内三人共用一台云服务器时 API 端口与产物如何隔离；
3. 组级验收以哪些证据为准，哪些证据可以引用队友的、哪些必须本人重跑。

## 候选方案

|编号|方案|问题|
|---|---|---|
|A|在服务器上再跑一次 `curl 127.0.0.1:8080`|与前两份证据重复，不是跨机|
|B|`server.py --host 0.0.0.0` 并在安全组开放端口|违反手册“无需开放公网 8080”，任务 API 无鉴权|
|C|另一台机器 `ssh -N -L 18081:127.0.0.1:8081`，客户端只访问本机 18081|符合手册；服务端口始终只绑定宿主 loopback|

## 决策

采用 **C**。

- **服务端**：本人仓库 `~/devops-students/241880106/buildchecker`，镜像 `course-e11e12:241880106`，`python3 run_e11e12.py serve --port 8081`。`run_e11e12.py` 只发布 `127.0.0.1:8081->8080`，任务目录 `work/api-jobs/` 位于本人工作副本，与 241880353（8080）、241880617 的任务互不覆盖。
- **客户端**：本人笔记本（macOS，`lima-mac.local`），不在服务器上执行。客户端脚本 `xmachine/e12_xmachine_client.sh` 只依赖 `bash/curl/jq/shasum`，因为该机器未安装 Python；B 组或其他同学在任意装有 curl+jq 的终端都可复用。
- **请求**：真实项目 E12（B1 bundle，base `0b62c79a…`，target `745ecf26…`），候选沿用 241880617 已入库的 `real-candidate.Dockerfile`（sha256 `c7b2ba5b…`），路径为 API 服务器上的 `/course/data/...`。
- **幂等键**：带组号和学号前缀 `a05-241880106-…`，避免与队友的键语义混淆。

## 验收口径

- 消费者只认 `e11e12-1` envelope：`schema_version/job_id/trace_id/kind/commit/status/data/artifacts`；产物以 `artifact://<job>/<relpath>` + SHA-256 定位。
- 下载核对三方一致：响应头 `X-Content-SHA256` = 清单 `sha256` = 客户端本地计算值，四份关键产物（patch、repair-plan、validation、recheck）全部一致才算通过。
- 组级验收清单（手册 03 §3 共 7 项）逐项指向证据文件；**可以引用**队友已入库、本人在服务器上复核过哈希/状态的证据；**必须本人重跑**的只有本人负责的跨机联调。
- 时间以服务器日志（UTC）为准。客户端笔记本系统时钟比服务器慢约 5 h 16 min，`summary.json` 中的客户端时间戳仅表示相对顺序。

## 后果

- 优点：跨机访问的证据不依赖服务器上的任何客户端；API 不暴露公网；三人端口与产物隔离。
- 代价：隧道每次请求约 2 s 往返；因 Docker 层缓存，真实项目任务在提交后 7 s 内即完成，未能在跨机侧观察到 `RESULT_NOT_READY (409)`。该行为由服务端 `server.py` 中 `result.json` 不存在即返回 409 的分支保证，本次如实记录为“未观测到”。
- 兼容性：不修改 `pipeline.py`、`server.py` 和任何公共接口，因此无需改动 `04_模板/接口契约.md`。
