### 3.3 两项实现细节（机器证据）

**细节 1：状态从 `QUEUED` 推进为 `RUNNING`，证明是同一对象**

若服务端在第二次请求时新建作业，状态会回到 `QUEUED`。返回 `RUNNING` 说明取到的是内存中同一 `state` 对象的实时快照，即「返回原作业」而非「返回等价的新作业」。

**细节 2：两个不同键的 `request_hash` 前缀相同**

```
KEY_REUSED : request_hash = 80c3ef1fc00f655565ef648eb90316…
KEY_CHANGED: request_hash = 80c3ef1fc00f655565ef648eb90316…
```

`server.py` 的 `Store.submit()` 中：

```python
digest = hashlib.sha256(json.dumps(request, sort_keys=True).encode()).hexdigest()
```

**哈希只覆盖输入，不覆盖 key**。这解释了两种行为的机制：

- 同键不同输入 → `digest` 变、`key` 不变 → 命中 `old != digest` → 409
- 换键同输入 → `digest` 相同、`key` 不同 → 未命中 `key in self.keys` → 新建
